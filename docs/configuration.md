# Configuration version 2

The default entrypoint is `.repo-policy/policy.yaml`. See
[policy bundles and contracts](policy-bundles.md) for thematic registries, automatic system
checks, Python checker placement and ID navigation. The rule entries below may be inline
in a manifest or in an explicitly registered `checks/*.yaml` module. A registry's definitions
become active through the manifest's `checks` list or referenced contract criteria.

The loader rejects unknown fields, duplicate ids/keys, invalid types, unsafe paths and unsupported
schema versions. YAML uses SafeLoader, disallows aliases and unsafe tags, and is limited to 1 MiB.
One explicit manifest selects local registries/contracts. No code evaluation, remote imports
or environment expansion occurs while loading configuration.

```yaml
version: 2
max_file_bytes: 1048576
exclude: ['generated/**', 'vendor/**']
rules:
  - id: readme
    kind: required-path
    path: README.md
    type: file
  - id: specifications
    kind: required-path
    path: specs
    type: directory
  - id: no-temporary-files
    kind: forbidden-path
    files: ['**/*.tmp']
  - id: no-debug-marker
    kind: forbidden-text
    files: ['src/**/*', 'specs/**/*.md']
    pattern: 'TEMP_DEBUG'
    severity: warning
    message: Remove the temporary debug marker
  - id: spec-status
    kind: frontmatter
    files: ['specs/**/*.md']
    keys: [id, status, updated]
  - id: data-syntax
    kind: syntax
    files: ['**/*.json', '**/*.yaml', '**/*.yml']
  - id: api-version
    kind: required-keys
    files: ['api/*.json']
    keys: [openapi, info, paths]
  - id: license-banner
    kind: required-text
    files: ['src/**/*.py']
    pattern: '^# SPDX-License-Identifier: MIT$'
  - id: asset-size
    kind: max-bytes
    files: ['assets/**/*']
    bytes: 524288
  - id: newline
    kind: final-newline
    files: ['**/*.py', '**/*.md']
    safe_fix: true
exceptions:
  - rule: license-banner
    files: ['src/generated.py']
    reason: Generated by the API generator; owned in its input template
plugins: []
```

Every rule has a unique stable `id`, `kind`, optional `severity` (`error`, `warning`, `info`),
`files` (default `['**/*']`), `exclude` and optional generic `message`. Required-path uses a literal
`path` and ignores `files`/`exclude`; reasoned exceptions can exempt it explicitly. Top-level
`exclude` filters file selection, not structural requirements. Exceptions match exact rule/plugin
ids; for external tools exempt the entire plugin for that path, or use the tool's native suppression.

Patterns are case-sensitive POSIX `fnmatch` patterns anchored to root-relative path strings.
`*` can match `/`; `**/` also matches zero directories. This is **not** gitignore syntax:
no negation, brace expansion or ordered reinclusion. `*.md` matches nested Markdown too.
Paths cannot be absolute, contain backslashes, NUL or parent `..` segments. Built-in exclusions
always omit `.git`, `.venv`, `venv`, `node_modules`, `__pycache__`, `.ruff_cache` path components.
Git submodule contents are not traversed in Git all/changed mode; run separately in a selected submodule.

Text rules require UTF-8 without NUL, including Markdown/code/spec files. A matching binary,
undecodable or oversized text file is an execution error, not a silent pass. Use path/size rules
for arbitrary binary files or explicitly exclude them from text rules. Size checks avoid decoding.
The read cap defaults to 1 MiB and can be raised explicitly to 100 MiB.

Text regex uses Python `re.MULTILINE` (add inline `(?s)` to match across newlines). Patterns and
config are trusted inputs; catastrophic backtracking has no engine-level timeout. Forbidden-text
emits one diagnostic per match; required-text emits one if absent. Messages do not include matched
content by default. JSON rejects duplicate keys and nonfinite values. YAML is the installed PyYAML
SafeLoader dialect (YAML 1.1 scalar resolution), with no aliases, merge keys or custom tags.
Multi-document YAML is unsupported; use a specialized YAML tool for those dialects.

Frontmatter is delimited by `---` on a line, at the start of a Markdown document. Required keys
are top-level mapping keys only, not JSON Schema validation. JSON/YAML rule locations reflect
parser marks where available; missing keys/paths use line/column 1. Config duplicate-key errors
identify a parse failure, without echoing source excerpts.

For `frontmatter`, optional `mapping_path` selects a nested mapping using a list of literal
key names. The default `[]` keeps the existing top-level behavior. A missing path or a
non-mapping target is a violation. Required `keys` always remain literal names: a key called
`metadata.created` is not interpreted as a path. Use this for formats with their own schema:

```yaml
rules:
  - id: markdown-dates
    kind: frontmatter
    files: ['**/*.md']
    exclude: ['skills/**/SKILL.md']
    keys: [created, updated]
  - id: skill-dates
    kind: frontmatter
    files: ['skills/**/SKILL.md']
    mapping_path: [metadata]
    keys: [created, updated]
```

Both rules together cover every selected Markdown file. Native skill metadata may contain
string dates such as `metadata: {created: '2026-10-26', updated: '2026-10-26'}` without
introducing unsupported top-level skill fields. These rules require presence only: values,
date format, ordering and actual freshness are not validated. `fix` does not generate dates;
an agent must establish their provenance and edit the document explicitly.

## Markdown reachability

Install the engine's optional `[markdown]` extra before enabling `markdown-reachable`.
The source checkout's dev lock already includes it. Missing parser dependencies are execution
errors (exit 2), never a successful skipped check. Parsing uses
[markdown-it-py](https://markdown-it-py.readthedocs.io/en/latest/using.html), with CommonMark
and table support; the engine does not reimplement Markdown syntax or render HTML.

```yaml
rules:
  - id: markdown-navigation
    kind: markdown-reachable
    files: ['**/*.md']
    roots:
      - AGENTS.md
      - .agents/skills/chosen-skill/SKILL.md
```

List only real entrypoints that exist in the selected repository. `roots` is a required,
nonempty, unique list of canonical literal repository-relative `.md` or `.markdown` paths.
Case matters: `AGENTS.md` and `agents.md` are different paths. Installed skill entrypoints
can be additional roots, including `.claude/skills/.../SKILL.md`. There is no automatic skill
discovery or reading of personal skill directories outside the checkout. For a personal skill,
keep its repository-specific guidance in the checkout and link it from the repository root.
Local and AF runs need the same files and roots; do not depend on a home-directory installation.

The graph contains all selected `.md`/`.markdown` files (suffix case-insensitive). Real inline,
reference and HTML anchor links form directed edges. Relative links resolve from the source
document; `/docs/page.md` resolves from the repository root. Percent-encoded paths are decoded
once, and query/fragment parts are ignored. A directory link resolves to its exact `README.md`
if present. Links in code, image alternatives, HTML comments, script/style/pre/code blocks,
YAML frontmatter and unused reference definitions do not create edges. An unclosed frontmatter
header contributes no edges. Plain-text paths, Claude `@file` imports, Markdown includes,
HTML navigation generated by scripts and external URLs do not create edges.

The rule traverses the complete graph even with `--changed` or `--files`: removing a link can
orphan an unchanged document. Top-level exclusions and built-in exclusions remove graph nodes;
rule-level `files`, `exclude` and reasoned exceptions filter violation targets, while intermediate
documents can still be traversed. Every configured root must exist as a safe selected file;
missing, globally excluded or symlink roots are violations regardless of target filters.
All graph inputs must be bounded UTF-8 without NUL, even when they are only transit nodes.
Links cannot escape the repository or follow symlinks. No URLs are fetched.

Reachable cycles are valid; an isolated cycle does not make its members reachable. Each
unreachable target produces a normal file/line/column/rule/severity diagnostic at 1:1,
exit 1 at the configured threshold, and `fixable: false`. Choose meaningful index links
explicitly; `fix` never invents navigation. This rule does not validate anchors or report
every broken link; use a dedicated link checker for that separate policy.

For policies containing graph rules, schema-version-1 JSON gains an additive optional
`repository_checks` array, one entry per graph rule with `rule`, `roots`, `files_checked`,
`reachable` and `unreachable` (ordered path lists). Top-level `files_checked` continues to
describe the requested file selection. Old policies retain their existing report shape;
the CLI and AF bridge emit identical reports for identical inputs.

Safe fixing appends LF or detected CRLF to a nonempty file; preserves existing bytes (including
Markdown hard-break spaces) and mode bits, refuses symlinks/hardlinks, checks concurrent changes
and replaces through an adjacent temporary file. Empty files remain empty. It does not preserve
timestamps, inode identity, extended attributes or ACLs; use check-only where these matter.
